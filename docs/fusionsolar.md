# Huawei FusionSolar — ไซต์ · อุปกรณ์ · ข้อมูลผลิต

ดึงรายชื่อไซต์ อุปกรณ์ และค่าการผลิตจาก FusionSolar Northbound API มาเก็บใน Firebase แล้วให้หน้าเว็บอ่านจากฐานข้อมูลอย่างเดียว
**ไซต์ Sungrow iSolarCloud ใช้โหนด/หน้าเดียวกันนี้** (`isc_ps_id` · id `SG-…` · รันคู่ขนานใน cron เดียวกัน) — ดู `docs/isolarcloud.md` · แก้โค้ดที่อ่าน `fusionsolar_station_code` ให้ใช้ `fsCodeOf(s)` / `fsVendor(s)`
**FusionSolar เป็นต้นทางของรายชื่อไซต์ · ซิงก์ไม่แก้/ไม่ลบข้อมูลงานในเว็บ (`jobs/` ไม่ถูกแตะสักฟิลด์)**

## การเชื่อมต่อ (ฝั่งเซิร์ฟเวอร์เท่านั้น — เบราว์เซอร์ไม่เรียก Huawei)
- Base `https://intl.fusionsolar.huawei.com/thirdData` (เปลี่ยนได้ด้วย env `FUSIONSOLAR_BASE` — ใช้ชี้ mock)
- **ฟังก์ชัน Vercel ต้องรันที่สิงคโปร์ (`"regions": ["sin1"]` ใน vercel.json)** — DNS ของ Huawei แยกตามประเทศ ถามจากสหรัฐฯ (ค่าเริ่มต้น iad1) ได้คำตอบว่าง → `ENOTFOUND intl.fusionsolar.huawei.com` (เจอ 2026-10-26) · ฐาน Firebase ก็อยู่ asia-southeast1 อยู่แล้ว
- env **`FUSIONSOLAR_USER`** = `api_tarnthanawat` · **`FUSIONSOLAR_PASS`** = รหัส — ตั้งใน Vercel → Settings → Environment Variables (Production) **ห้ามเขียนลงโค้ด/Git**
- ทุกคำขอ POST JSON · `/login {userName, systemCode}` → token จาก header `xsrf-token` + เก็บ cookie → คำขอถัดไปส่ง `XSRF-TOKEN` + cookie เดิม
- login ครั้งเดียวต่อรอบ · **failCode 305** → login ใหม่แล้วลองซ้ำครั้งเดียว
- **login ไม่ผ่าน = หยุดทั้งรอบทันที** (ไม่ลองรหัสผิดซ้ำทุกชุด — เสี่ยงบัญชีถูกล็อก) · แปล failCode เป็นเหตุจริง (`loginFailText`: 20001 ไม่พบบัญชี · 20002 ถูกปิด · **20003 บัญชี Northbound หมดอายุ** · 20400 รหัสผิด)
  - จด `fsState/login_fail` `{since, at, failCode, message, text}` → หน้าไซต์ทั้งหมด + หน้า log ขึ้นป้ายแดง `FsSyncAlert` ให้ทุกคนเห็นว่าตัวเลขค้าง · ล็อกอินผ่านครั้งไหนลบทิ้งเอง
  - รอบอัตโนมัติ (cron/gh/view) เว้น 1 ชม. หลังพลาดก่อนลองใหม่ (log `skipped`) · แอดมินกด "ซิงก์ตอนนี้" ลองได้ทันที
  - **เจอจริง 2026-10-26 22:08 น.: 20003 "northbound system has expired."** — ไม่ใช่รหัสผิด ต้องให้แอดมินบริษัทใน FusionSolar ต่ออายุบัญชี `api_tarnthanawat` (System → Company Management → Northbound Management · บัญชี API มีวันหมดอายุ)
- **failCode 407** (ถี่เกิน) → หยุดทั้งรอบ จด `fsState/blocked_until` = +15 นาที เก็บ cursor ไว้ทำต่อ · รอบที่เริ่มก่อนเวลานั้นข้าม (มี log `skipped`)
- เว้นทุกคำขอ ≥ 3 วินาที (`FUSIONSOLAR_GAP_MS`) นับข้ามรอบด้วย `fsState/last_call_at`
- ทุกคำขอที่พลาดจด `{at, api, failCode, message}` ลง `errors` ของ log
- id อุปกรณ์ 16 หลักเกิน 2^53 → แปลงเป็นสตริงก่อน `JSON.parse` (`parseBody`)

## โหนดในฐานข้อมูล (สเปกเขียนเป็นตาราง SQL — แอปใช้ RTDB จึงทำเป็นโหนด เขียนทีละฟิลด์)
**`fsSites/{siteId}`** — id = `FS-<code>` (อักษรนอก A-Z0-9 → `_` เช่น `FS-NE_57489892`) · ไซต์ที่เพิ่มเอง `FSM-…`
- ซิงก์เขียน: `name` `fusionsolar_station_code` `capacity_kw` `address` `source` (`fusionsolar`|`manual`) `fs_status` (`found`|`not_found_in_fusionsolar`) `last_synced_at` · KPI: `day_kwh` `month_kwh` `total_kwh` `health_state` `kpi_updated_at`
- ผู้ใช้เขียน (ซิงก์ไม่แตะ): `jobIds {jobId:true}` `note` · ไซต์เพิ่มเอง: `created_at` `created_by` · รวมไซต์: `merged_into` `merged_at` `merged_by`
- ไซต์ที่มีอยู่แล้ว ซิงก์อัปเดตแค่ name / capacity_kw / address / last_synced_at (+ fs_status) · ไม่พบใน FusionSolar = ตั้ง `not_found_in_fusionsolar` **ไม่ลบ** · กลับมาเจอ = `found`
- ไซต์ `manual` ที่ผูกรหัสแล้ว ซิงก์รอบแรกเก็บค่าที่ผู้ใช้กรอกไว้ใน `manual_name` `manual_address` `manual_capacity_kw` (`manual_saved: true`) ก่อนเขียนทับ · `source` ยังเป็น `manual`

**หยุดซิงก์ไซต์** (ผู้ใช้สั่ง 2026-10-28 "ไซต์ที่ไม่ได้ดูแลแล้ว ไม่ต้องดึงข้อมูล") — `fsSites/{id}/sync_off = { at, by }` แอดมินกดในหน้าไซต์ แท็บ "ข้อมูลและงาน" (askConfirm) · **ไม่ลบไซต์** (ลบแล้วรอบ sites สร้างใหม่ + ประวัติหาย)
- เซิร์ฟเวอร์ (`syncOn` ใน fusionsolar.mjs · isolarcloud.mjs): ไม่ดึงรายชื่ออุปกรณ์/ค่าอุปกรณ์/ค่าผลิต/ย้อนหลัง · รายชื่อสถานียังอัปเดต (1 คำขอ ไม่งั้นไซต์ถูกสร้างซ้ำ) · Sungrow ไม่เขียน day_kwh/health ของไซต์นั้น
- หน้าไซต์ทั้งหมด: ไม่นับในยอดรวม/อันดับ/เรื่องที่ควรดู · ชิป "หยุดซิงก์" ดูรายการ · หน้าไซต์มีแถบ "หยุดซิงก์แล้ว" + ปุ่มซิงก์ต่อ · Huawei ถามทีละ 100 ไซต์ จำนวนคำขอแทบไม่ลด ที่ลดคือข้อมูลที่เขียน/ส่งให้หน้าเว็บ

**`fsDevices/{devId}`** — `fusionsolar_dev_id` (สตริง) `site_id` `station_code` `dev_name` `dev_type_id` `esn_code` `model` `software_version` `last_kpi_json` (JSON สตริงของ dataItemMap) `last_kpi_at` `fs_status`

**`fsSyncLogs/L<เวลา>`** — `started_at` `finished_at` `job` `trigger` (cron/gh/manual/tool) `by` `ok` `skipped` · ไซต์ `created` `updated` `not_found` · อุปกรณ์ `dev_created` `dev_updated` `dev_not_found` · `stations` `kpi_sites` `kpi_devices` `hist_months` `hist_days` `hist_hours` `requests` `pending` `errors[]` `note` `ms`

**`fsKpiDay/{siteId}/{YYYY-MM-DD}`** — `kwh` (ผลิตทั้งวันล่าสุด) · `h/{HH}` ผลิตสะสมของวันถึงรอบซิงก์ชั่วโมงนั้น · `p/{HH}/{devId}` kW ของอินเวอร์เตอร์ตอนซิงก์ · `m/{HH}/{devId}` = `{a: active_cap, r: reverse_active_cap}` ตัวนับสะสมของมิเตอร์ (47/17) ตอนซิงก์ · `u/{HH}` ใช้ไฟสะสมของวัน (เขียนโดย job hist จาก `use_power`) — รอบ KPI เขียน h/p/m เองไม่ยิง API เพิ่ม · วัน/ชั่วโมงตามเวลาไทย
**`fsKpiMonth/{siteId}/{YYYY-MM}`** — ผลิตทั้งเดือนล่าสุด (kWh)
ประวัติเริ่มนับวันที่ซิงก์ KPI รอบแรก · ชั่วโมงที่ซิงก์พลาด ผลต่างไปรวมกับแท่งถัดไป (กล่องค่าบอกช่วงเวลาจริง)

**กราฟวันนี้ = กำลังไฟ kW ตามเวลาจริง** (ผู้ใช้สั่ง 2026-10-27 "ต้องเป็นกราฟ kW ไม่ใช่หน่วย") — `w/{HHmm}` = `{ pv: kW รวมอินเวอร์เตอร์ของไซต์, g: { มิเตอร์: kW ดิบ } }` จดทุกรอบ KPI (Huawei + Sungrow · `fsWKey`/`fsWPatch` ใน fusionsolar.mjs · HHmm ปัดลง 5 นาที)
- หน้าเว็บ: เส้นโซลาร์ + เส้นใช้ไฟ (= pv − ขาย · ทิศมิเตอร์ตาม `em.revIsExport` · มิเตอร์ตัวเดียวกับ `em.meter`) · แกนเวลาจริง `FsTrendChart mode="time"` (t0/t1 นาที · ห่าง > 75 นาที = เส้นขาด) · ไม่มี w ใช้ `p/{HH}` เป็นจุด ≈HH:00 · จุด "ตอนนี้" = `em.pvKw/loadKw`
- **จุดต้องครบในตัวเอง** (ผู้ใช้แจ้ง 2026-10-27 กราฟขาดเป็นจุด ๆ): รอบ KPI แบ่งหลายรอบ (งานค้าง) — รอบหนึ่งได้แต่อินเวอร์เตอร์ อีกรอบได้แต่มิเตอร์ ตอนจด w อุปกรณ์ของไซต์ที่รอบนี้ไม่ได้ดึงจึงใช้ `last_kpi_json` ที่อายุ ≤ 20 นาที · หน้าเว็บแกนเวลาจุดไม่มีค่า = ข้ามไม่ตัดเส้น และจุดที่มีแต่มิเตอร์ยืม pv จากจุดใกล้สุด ≤ 20 นาที (ข้อมูลเก่าก่อนแก้)
- ผังหน้ารายละเอียด (ผู้ใช้สั่ง): การ์ด "กำลังไฟวันนี้" → การ์ด "ผลิตย้อนหลัง" (ปุ่มสลับ 30 วัน / 12 เดือน) → "พลังงานไปไหน" (`FsHistoryCard only="day" | "hist"`)
- ไซต์ที่อินเวอร์เตอร์แบ่งอยู่สองรอบ (งานค้างข้ามรอบ) ค่า pv ของจุดนั้นจะขาด
- **เลือกดูวันก่อนหน้าได้** (ปุ่ม ‹ › · ผู้ใช้: "วันก่อนหน้าก็ดูไม่ได้") ย้อนได้ถึงวันแรกที่มีใน fsKpiDay (โหลด 32 วัน) · ช่วงที่ไม่มี w = **kW เฉลี่ยรายชั่วโมง** จากตัวนับสะสม: ผลิต Δh · ใช้ไฟ Δu (use_power) หรือมิเตอร์ (ผลิต + Δซื้อ − Δขาย) · ช่วงห่างเกิน 3 ชม. ไม่คิด · ไม่มีคู่ = p/{HH} (≈ ค่าตอนซิงก์)
- **job `histday`** (Vercel cron 04:30 ไทย `?job=histday`) = /getKpiStationHour เมื่อวาน+วันนี้ ~2 คำขอ ไม่ใช้ hist_cursor → ทุกวันมีรายชั่วโมงครบ (มีไฟที่ใช้) แม้ซิงก์พลาด · job hist ปุ่มแอดมินดึงรายชั่วโมง **7 วัน** (เดิม 2)
- **รอบ kpi เติมรายชั่วโมงของวันนี้เอง ชั่วโมงละครั้ง** (`fsState/hourfill_at` · 1 คำขอ · ทำเมื่อเหลือเวลาในรอบ) — GitHub ข้ามรอบบ่อย/บัญชีหมดอายุ ทำให้กราฟวันนี้มีจุดเดียว (ผู้ใช้: "กราฟมันไม่มีอะไรเลย" 2026-10-27)

**กราฟรายชั่วโมงแบบเดิม (kWh ต่อชั่วโมง — เลิกแสดงแล้ว ข้อมูล h/m/u ยังเก็บ)** (ผู้ใช้สั่ง 2026-10-26: "กราฟควรเป็นสองอันคือโหลดกับโซลาร์") — เส้นใช้ไฟ (`--fs-load` น้ำเงินคราม) เป็นพื้นที่ใต้เส้นโซลาร์ ส่วนที่ซ้อนกัน = ไฟโซลาร์ที่ใช้เอง · มีไฟที่ใช้ = แกนทั้งวัน 0–23 น.
- ไฟที่ใช้ต่อช่วง: มี `u` ใช้ผลต่างของ `u` ก่อน · ไม่มีใช้มิเตอร์ = Δผลิต + Δซื้อ − Δขาย (ทิศมิเตอร์ตาม `fsEnergyModel().revIsExport`) · ต้องเป็นมิเตอร์ชุดเดียวกันทั้งสองรอบ ไม่งั้นช่วงนั้นว่าง · ไม่รวมแบตเตอรี่ (ไซต์มีแบต ค่าจะคลาดเท่าที่ชาร์จ/คาย)
- ไซต์ไม่มีมิเตอร์ = ไม่มีเส้นใช้ไฟ (กราฟเหมือนเดิม)

### ข้อมูลย้อนหลัง (job `hist` — ผู้ใช้สั่ง 2026-10-26 ให้กราฟไม่ต้องรอเก็บเอง)
- ปุ่ม **"ย้อนหลัง (กราฟ)"** ในหน้า log การซิงก์ (แอดมิน) · `node tools/fusionsolar-run.mjs hist [--write] [--mock]` · ไม่อยู่ใน all — กดเองเมื่อต้องการ (รายชั่วโมงเมื่อวานมี cron histday ทุกวันแล้ว)
- คิวตายตัวต่อวัน ทีละ 100 สถานี: `/getKpiStationMonth` ปีที่แล้ว+ปีนี้ → `/getKpiStationDay` เดือนที่แล้ว+เดือนนี้ → `/getKpiStationHour` 7 วันล่าสุด (109 ไซต์ = 22 คำขอ ≈ 2–3 รอบกด) · ไม่ทัน = `fsState/hist_cursor` + `hist_key` (วันที่ของคิว ข้ามวัน = เริ่มใหม่) · ครบ = `hist_done_at`
- ส่ง `collectTime` = เที่ยงวันไทยของวัน/กลางเดือน/กลางปี · ค่าที่ได้ `collectTime` = เวลาเริ่มของช่วง → แปลงเป็นวัน/ชั่วโมงไทย · ค่าผลิต `inverter_power` ไม่มีใช้ `PVYield`
- ไม่เขียนทับค่าสด: วันนี้ไม่เขียน `kwh` · เดือนนี้ไม่เขียน `fsKpiMonth` · ชั่วโมงที่ยังไม่จบไม่เขียน
- รายชั่วโมง → `h/{HH+1}` = ผลิตสะสมของวันถึงปลายชั่วโมง HH (ความหมายเดียวกับค่าที่รอบ KPI จดตอน HH+1:07) · ชั่วโมง 23 ไม่เขียน
- พลาดทีละคิว (เช่นบัญชีไม่มีสิทธิ์ API นี้) = จด error แล้วทำคิวถัดไป · 407/ล็อกอินพลาด = หยุดทั้งรอบเหมือนงานอื่น
- **ยังไม่ได้ลองกับ Huawei จริง** (ทดสอบกับ mock + ฐานทดสอบเท่านั้น) — ชื่อ field/ความหมาย collectTime ตามเอกสาร Northbound ถ้าของจริงต่างให้แก้ที่ `doHist`

## ผูกกับงานในเว็บ — ทำไมแยกโหนด
ไซต์ ≠ ใบงาน: ไซต์หนึ่งมีได้หลายงาน (ติดตั้ง · ขยายระบบ) และไซต์ใน FusionSolar อาจไม่มีงานของเราเลย → เก็บที่ `fsSites` ผูกด้วย `jobIds` · ไม่เขียนลง `omSites` (จะทำให้ O&M แจ้งเตือนรอบล้างแผง/ประกันของไซต์ที่ไม่ได้ขายบริการ)
หน้ารายละเอียดไซต์แสดงงานที่ผูก (เปิดใบงานได้) และปุ่ม "ทะเบียน O&M" ถ้า `omSites/<jobId>` มีอยู่

## รวมไซต์ (ไซต์เพิ่มเองที่รหัสซ้ำกับไซต์ที่ซิงก์มา)

- บ้านใช้ = โซลาร์ − ขาย − ชาร์จแบต · ใช้เอง = ผลิตสะสม − ขายสะสม · พึ่งตัวเอง = ใช้เอง ÷ (ใช้เอง + ซื้อ) — คิดจากตัวเลขสะสม ถูกเมื่อมิเตอร์ติดพร้อมระบบ (หน้าเว็บมีหมายเหตุบอก)
- CO₂ = kWh × 0.4999 kg (ค่า Grid Emission Factor ของไทย อบก.)
- "ควรดู": ออฟไลน์/มีปัญหา/ไม่พบ · ข้อมูลผลิตค้าง > 3 ชม. · อินเวอร์เตอร์สถานะหยุด (768–774, 45056) · อุณหภูมิ ≥ 75 °C · สตริงกระแสต่ำ (เช็กเฉพาะ 09–15 น.) · แบตผิดพลาด · ด็องเกิล/ล็อกเกอร์ขาดการเชื่อมต่อ · **เฉลี่ยต่อวันของเดือนนี้ต่อ kWp < 60% ของค่ากลางไซต์อื่น** (ตั้งแต่วันที่ 3 ของเดือน · ต้องมีไซต์ปกติ ≥ 3) — เดิมเทียบ "วันนี้" แต่ข้อมูลจริงวันอาทิตย์เตือนผิด 20+ ไซต์ (โรงงานจำกัดการขายไฟ ไม่มีโหลด = ผลิตต่ำ)
- อุปกรณ์ชนิดเดียวกันเกิน 8 ตัวที่ไม่ใช่อินเวอร์เตอร์/มิเตอร์/แบต รวมเป็นการ์ดเดียว: จำนวน · รุ่น · กดดูรายชื่อ + ค้นหา
- การ์ด "พลังงานไปไหน · มาจากไหน" (`FsEnergyCard`) **โทนส้มเดียวกับกราฟประวัติ** (ผู้ใช้ 2026-10-28 แบบเขียว/ฟ้า/แดง "ไม่เข้าธีมส้ม" · แบบหน้าปัด+แถบสเกลเดียวกัน "ดูงง"): แถวตัวเลข ใช้เองได้ % · พึ่งโซลาร์ได้ % · CO₂ + รางสองเส้นแยกสเกล — โซลาร์ = ส้มไล่สีเรือง · ขาย = ส้มอ่อน · ซื้อจากกริด = เทา
- สีสัดส่วนพลังงาน `--fs-self` `--fs-exp` `--fs-imp` (ผ่านตัวตรวจสี dataviz ทั้งสว่าง/มืด) · กราฟชุดเดียวใช้ `--primary`
- มือถือ: index.html บังคับ grid ใน `.app-content` เป็นคอลัมน์เดียว → ช่องตัวเลข 2 คอลัมน์ใส่ `className="kpi-grid"` · แถวสตริงใช้ flex
